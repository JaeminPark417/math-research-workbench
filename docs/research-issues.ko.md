# 로컬 이슈로 연구 과정 관리하기

[English guide](research-issues.md)

이슈는 주장, 필요한 lemma, 미해결 증명 단계, 반례, 검토, 실행할 활동을 담는 작은 연구 기록입니다. 어떤 경로를 골랐는지, 무엇이 실패했는지, 어떤 근거가 적용되는지, 다음에 무엇을 할지 연결해 보존합니다. 연구 폴더의 일반 파일로 저장하므로 외부 서비스·계정·새 화면이 필요하지 않습니다.

## 프로젝트 하나부터 적용하기

Codex에 다음처럼 요청하세요.

```text
이 프로젝트에 이슈 기반 관리를 적용해 줘. 현재 상태부터 읽고,
기존 주장 ID를 재사용하고, 실패한 접근과 반례를 보존해 줘.
초기 이슈 지도에 아직 포함하지 않은 범위도 알려 줘.
```

Codex는 이 범위만 등록하고 요청한 연구를 진행할 때 기록을 유지합니다. 그 안의 일상적인 로컬 갱신마다 허락을 다시 묻지 않습니다. 모든 프로젝트를 자동 이관하거나 사용자가 없을 때 연구를 시작하지 않습니다. 다음 세션에서는 이렇게 이어갈 수 있습니다.

```text
이 프로젝트를 이어서 연구하자. 현재 활동, 근거, 아직 이관하지 않은
다음 행동을 확인하고 목표에 맞는 다음 단계를 진행해 줘.
```

현재 상태만 물으면 활동을 시작하지 않습니다. 이슈 목록이 비어 있어도 이전 노트나 다른 연구 경로가 초기 범위 밖에 남아 있을 수 있습니다.

“마지막에 왜 실패했는지, 어떤 gap이 남았는지, 어느 티켓을 열어 무엇부터 할지 네 줄로 보여줘”라고 요청할 수 있습니다. Codex는 근거를 연결하고, 작업이 일시 중지된 상태라면 재개 조건도 표시합니다.

## 현재 행동 목록은 한 곳에 두기

등록 범위 안의 현재 행동·우선순위·활동 상태는 티켓을 정본으로 합니다. 프로젝트 중심축에는 수학적 정본, 전략, 아직 이관하지 않은 작업과 관련 티켓 링크를 둡니다. 세션 노트와 연구 로그에는 당시 결과를 기록하고 현재 행동으로 연결하며, 같은 작업 목록을 다시 관리하지 않습니다. 진행 중인 수학 연구 run을 담당하는 티켓이 없다면 해당 run에 그 범위의 바로 다음 단계를 두고 중심축에서 링크합니다.

짧은 설명, 작은 노트 수정, 우선순위 정리, 상태 질문에는 새 활동이나 운영 세션이 필요하지 않습니다. Codex는 해당 작업에 필요한 조회와 지침만 사용합니다. 실제 활동 수행을 요청하면 그 활동의 세션을 시작하거나 이어서 사용하고 결과를 보존합니다.

## 논문 읽기와 원고 작성 중 사용하기

```text
이 논문을 읽으면서 main theorem과 사용하는 lemma를 연결해 줘.
정확한 가정, 아직 확인하지 못한 증명 단계, 범위를 한정한 반례를 기록해 줘.
```

```text
원고를 구성하고 수정하는 동안 주요 주장, 공유 lemma, 빠진 논증,
다음 집필 행동을 프로젝트 이슈에 연결해 줘.
문장이 바뀌어도 이전 검토와 당시 출처 버전을 보존해 줘.
```

외부 논문 정독은 기존 paper 노트 옆에 기록하며, 작성 중인 원고는 기존 프로젝트에서 관리합니다. 여러 정리가 사용하는 lemma는 하나의 기록을 공유합니다. 이슈 지도만으로 인용이나 원문 주장이 검증되지는 않습니다.

## 완료의 의미

Done은 실행 활동에만 붙으며 해당 일을 수행했다는 뜻입니다. gap을 발견한 검토나 부정적 결과가 나온 계산도 완료될 수 있습니다. 정리가 증명되었다는 뜻은 아닙니다. 주장과 gap의 기준은 프로젝트 Research State Spine, 상세 research-run 기록, 연구자의 명시적 수학적 판단입니다.

연구 활동의 짧은 운영 세션 여러 개가 하나의 장기 수학 연구 run을 참조할 수 있습니다. 별도의 읽기 쉬운 세션 요약은 실질적인 연구나 결정이 있을 때 남기며, 티켓을 수정할 때마다 만들지는 않습니다. 실패한 접근과 반례를 보존하고, 우선순위에는 이유를 적어 새 근거에 따라 다시 판단합니다.

## 파일·비공개 백업·복구

프로젝트 기록은 `projects/<slug>/tickets/`, 논문 기록은 기존 노트 옆 `<slug>/tickets/`에 저장됩니다. Markdown은 Codex 없이도 읽을 수 있습니다. 편집은 Codex와 공용 writer를 통해 진행하여 관계와 근거 버전을 함께 유지하고, 파생 검색 index는 직접 수정하지 마세요.

실제 이슈는 미공개 연구 자료입니다. 백업·공유 전 기존 승인 절차와 정확히 private인 목적지 확인을 따릅니다. 실제 이슈 저장소를 공개 Workbench 배포 저장소에 push하지 마세요. 캐시·잠금·복구 journal은 Git 백업에서 제외하며 정본 티켓·운영 세션·작업 영수증은 보존합니다.

다른 컴퓨터에서는 workspace 내부 capsule/paper 참조를 그대로 사용할 수 있습니다. 별도 Git clone을 등록했다면 로컬 경로와 origin을 명시적으로 확인해야 합니다. workspace는 클라우드 동기화 폴더 밖에 둡니다. 쓰기가 중단되면 Codex에 복구 상태 검사를 요청하고 알 수 없는 외부 변경을 보존하세요. 강제로 진행하려고 잠금이나 pending journal을 지우지 마세요. 복구 기능이 디스크 고장이나 정전까지 보장하지는 않습니다.

사용자가 터미널 명령이나 JSON을 작성할 필요는 없습니다. 유지보수자는 [에이전트 workflow](../meta/research-ticket-workflow.md), [쓰기 계약](../meta/research-tickets/WRITE-API.md), [테스트 안내](../meta/research-tickets/TESTING.md)를 참고할 수 있습니다. 실행 환경은 Python 3.9 이상이면 됩니다.
